# 012 - Fix Multimodal Tokenizer Dimension Mismatch in DataLoader

## Context
During the `app.py train` step for `gemma-4-e2b`, the script crashed inside the PyTorch `DataLoader` worker process with `ValueError: expected sequence of length 657 at dim 2 (got 101)`.

This crash was caused by Gemma 4's multimodal `Processor`. Because it natively supports images and video inputs alongside text, calling `tokenizer(text=prompt)["input_ids"]` automatically wraps the text token sequence into a batch dimension (returning `[[1, 2, 3...]]` instead of `[1, 2, 3...]`). 
During dynamic padding in the `Text2CypherCollator`, PyTorch attempts to stack these jagged nested arrays into tensors, which immediately fails.

## Modifications
- **src/data/dataset.py**: 
  - Added a defensive `_flatten_ids(ids: Any)` helper function to ensure that no matter the tokenizer/processor output (1D list, 2D list, or 2D tensor), it is aggressively flattened to a flat 1D list of integers.
  - Rewrapped the outputs of `tokenizer(text=prompt)["input_ids"]` throughout `_target_ids`, `tokenize_examples`, `preview_example`, and `token_length_stats` with this `_flatten_ids()` helper.
