# Log 026: Resume Failure from Adapter-Only Emergency Checkpoint

**Context:**
Resuming qwen3.5-2b-enhanced on Kaggle (session 20261013-112058-kaggle) failed with
`FileNotFoundError: .../checkpoint-1694/trainer_state.json`. Step 1694 is not a multiple of
`save_steps: 50`, so the trainer's periodic save did not create it. The `KeyboardInterrupt`
handler in `train.py` did: it saved the adapter with `trainer.save_model()` (weights only, no
trainer/optimizer/scheduler/RNG state) and pushed it to the Hub as `checkpoint-1694`.
`_do_push` then pointed `LATEST.json` at it and pruned, keeping the two highest steps.
On the next session, `resolve_resume` followed `LATEST` to a folder that cannot be resumed.
Lane stops in `kaggle.ipynb` (SIGINT on interrupt/SIGTERM) trigger this handler.

**Modifications:**
- **`src/training/train.py`:** the emergency path calls `trainer._save_checkpoint()` to write a
  full `checkpoint-<step>` and pushes it with fingerprint metadata. If that fails, adapter
  weights go to `<output_dir>/interrupted` locally and are never uploaded as a checkpoint.
- **`src/training/checkpointing.py`:**
  - `is_resumable_checkpoint()` (requires `trainer_state.json`) and `checkpoint_metadata()`.
  - `_do_push` writes `LATEST.json` only for resumable checkpoints.
  - `pull_resumable()` chooses the newest remote checkpoint that contains
    `trainer_state.json` (from the repo file listing), warns about skipped incomplete ones, and
    raises instead of silently restarting when the Hub cannot be listed or nothing is
    resumable. `resolve_resume` uses it.
  - `prune()` counts only resumable checkpoints towards `keep_last` and never deletes anything
    newer than the oldest kept resumable checkpoint.
