# 004 — Initial source implementation (`src/` + `app.py`)

## Context

Standing up the whole capstone pipeline from scratch: LoRA fine-tuning on Colab free tier,
GGUF inference on the ThinkPad, Neo4j execution accuracy, and a checkpoint scheme that
survives cycling between Google accounts.

## Changes & Reasons

**Entrypoint**

- `app.py` — argparse CLI with subcommands `doctor`, `data`, `train`, `predict`,
  `evaluate`, `export`, `checkpoint`, `neo4j`. Argparse rather than Typer/Click so the
  entrypoint has zero third-party deps and always runs, even in a half-broken env.

**Config & environment**

- `src/config.py` — dataclass config tree + `MODEL_REGISTRY` for the four models we
  settled on (gemma-4-E2B/E4B, Qwen3.5-2B/4B). Registry carries per-model facts the code
  can't infer: Gemma needs `eager` attention (final_logit_softcapping) and rejects a
  `system` role; Qwen3.5 needs `enable_thinking: False` or its template injects a
  `<think>` block into every prompt.
- `RunConfig.fingerprint()` hashes the training-relevant settings. Resume refuses to
  continue if the remote checkpoint's fingerprint doesn't match — stops us silently
  resuming a `schema_mode: enhanced` checkpoint into a `exact_match` run.
- `src/env.py` — `doctor` command. Explicitly flags "T4 has no bf16" as expected rather
  than as an error, since that will otherwise look like a bug every session.
- `src/paths.py` — Colab vs laptop path resolution; artifacts go to `/content/artifacts`
  on Colab (fast local disk) with durability coming from the Hub, not the filesystem.

**Data**

- `src/data/prompts.py` — instruction text lifted verbatim from Ozsoy et al. Table 3 so
  our zero-shot baselines are comparable to their published numbers on the same dataset.
  Single `render_prompt()` used by both backends → GGUF and HF runs get byte-identical
  prompts.
- `src/data/schema_filter.py` — parser handling both schema dialects in the dataset, plus
  base/exact-match/NER-masked/similarity filters (Ozsoy 2025 §3). Over-pruning falls back
  to the full schema: an empty schema guarantees a wrong query, which would make the
  ablation meaningless.
- `src/data/dataset.py` — manual tokenisation with `-100` label masking on prompt tokens.
  Chose plain HF `Trainer` + custom collator over TRL's `SFTTrainer` to avoid depending on
  a response-template string that changes per chat template. Also schema-aware truncation:
  over-length rows drop property lines rather than getting silently left-truncated through
  the answer.

**Training**

- `src/training/model_loader.py` — tries Unsloth, falls back to transformers+peft on any
  failure. Both target models are multimodal wrappers, so `AutoModelForCausalLM` may not
  resolve — there's a class cascade. LoRA targets are discovered by walking the module tree
  (excluding vision/audio/embeddings) instead of hardcoding `q_proj`/`k_proj`, which won't
  exist in Qwen3.5's linear-attention blocks.
- `src/training/checkpointing.py` — the account-cycling piece. Private HF repo as source
  of truth; `LATEST.json` marker written only *after* the folder upload commits, so a
  session killed mid-upload falls back to the last complete checkpoint. Uploads run in a
  background thread so the GPU doesn't stall. Also a `WallClockLimitCallback` that stops
  and saves after N minutes — better to end a session deliberately than get reclaimed.
- `src/training/train.py` — `_filter_training_args()` drops TrainingArguments this
  transformers version doesn't accept (`eval_strategy` vs `evaluation_strategy`), so we
  don't have to pin a version.

**Inference & export**

- `src/inference/llama_cpp_backend.py` — drives `llama-server` over HTTP rather than
  binding llama-cpp-python. No ABI-tied compile step, and it reuses the binary we already
  build for interactive use.
- `src/export/gguf.py` — fails loudly with diagnostics if `convert_hf_to_gguf.py` doesn't
  know the architecture. Gemma 4's per-layer embeddings and Qwen3.5's linear attention are
  both very recent; if upstream support isn't there yet that's a finding for the thesis,
  not a bug to hide.

**Evaluation**

- `src/evaluation/metrics.py` — Google-BLEU implemented directly rather than via
  `evaluate`, which downloads a metric script at runtime (bad on flaky Colab, impossible
  offline on the laptop). Added `classify_complexity()` so results break down
  easy/medium/hard/extra_hard per Lyu et al. §4.5 — directly serves sub-question 2.
- `src/evaluation/neo4j_client.py` — `demo` provider maps `neo4jlabs_demo_db_fincen` →
  Neo4j Labs' hosted server (user == password == db name), same target Ozsoy et al. used.
  On-disk result cache means the gold query for each instance executes once across all
  model comparisons. Rows sorted lexicographically unless the gold query has `ORDER BY`,
  in which case order is preserved.

**Scripts**

- `scripts/install_neo4j_debian.sh` — bare-metal APT install, Java 21, conservative
  heap/pagecache for a laptop, `default_to_read_only` so a generated query can never
  mutate the graph. Documents the Community Edition single-database constraint.
- `scripts/build_llama_cpp.sh`, `scripts/colab_bootstrap.sh`.
