# Log 034: numpy Replaced Under a Running Kernel (Kaggle CPU Edge Session)

**Context:**
The second edge-eval session got through all exports (merge and conversion run as subprocesses). It then crashed
in the benchmark cell when building prompts in the kernel. `load_tokenizer` imports transformers, which imports
scikit-learn, then scipy, then numpy's lazily loaded `numpy.char`. That submodule failed with
`ImportError: cannot import name '_slice' from 'numpy._core.umath'`.

The Kaggle kernel imports numpy at startup (matplotlib inline backend). The pip installs in cell 50 (bootstrap
requirements and/or `gguf-py`) then replaced numpy on disk. Lazy submodules came from the new files and clashed
with the old compiled modules already in memory. A kernel restart would avoid it, but a committed (batch) run
cannot restart.

**Modifications:**
- **`notebooks/edge-eval-kaggle/50-install-build.py`:**
  - Before any install, writes `pip-constraints.txt` with the installed versions of numpy, scipy, pandas,
    scikit-learn and pyarrow, and exports `PIP_CONSTRAINT`. Every pip call inherits it, including those in
    `colab_bootstrap.sh`. A conflicting requirement now fails at install time and names the package.
  - Records which of those modules the kernel had imported at start.
  - After all installs, raises if any frozen package changed on disk, or if an imported module's in-memory
    version differs from the one on disk.
  - Runs a subprocess import smoke test (numpy.char, scipy.sparse, sklearn, transformers AutoTokenizer).
