# Log 029: Negative Error Bars in Final-Evaluation Figures

**Context:**
`notebooks/final-eval-kaggle.ipynb` crashed in cell 11 (figures). Matplotlib raised
`ValueError: 'yerr' must not contain negative values` while drawing Figures 1-3. The error bars
are drawn as `value - ci_low` and `ci_high - value`, and two sources can make one negative:
- **Wilson interval at p = 0 or p = 1.** The exact lower bound at p = 0 is 0, but floating-point
  rounding can return about 1e-17, so `value - ci_low` < 0. The same happens at the upper bound
  when p = 1. Zero exact matches is plausible for zero-shot jobs, especially Gemma 4 E2B, which
  uses the plain-text prompt fallback.
- **Percentile bootstrap CI for corpus GLEU.** It is computed on the pooled-count statistic
  `min(overlap/hyp, overlap/ref)` and is not guaranteed to contain the point estimate.

**Modifications:**
- **`notebooks/final-eval-kaggle.ipynb`:**
  - Cell 10: `wilson()` now returns `(min(lo, p), max(hi, p))`, so the reported interval always
    contains the proportion. This also corrects the CSV and LaTeX tables, not just the figures.
  - Cell 11: error bars are clipped at zero with `np.clip(..., 0, None)`. The GLEU bootstrap
    interval itself is unchanged, because it is a legitimate percentile interval.
  - Cell 12: the bundle README caveats state that GLEU bootstrap intervals may not contain the
    estimate, and that the figures clip at it.
- **Recovery:** no job needs recomputing. Committing a new version reuses all finished jobs from
  `final-eval/<eval_tag>/jobs/` (`SKIP_COMPLETED_JOBS`); only aggregation, figures and export run.
- **Pending:** apply the same two code edits (Wilson clamp, `yerr` clip) to
  `notebooks/final-eval-colab.ipynb`, which has the identical bug.
