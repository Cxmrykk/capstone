# Log 035: GGUF Converter Dependencies Without Building gguf-py; Edge-Notebook Fixes

**Context:**
The third edge-eval session (20261015-134104-kaggle-cpu) failed in cell 50 at `llama-convert-deps` (exit 1).
That step ran `pip install <llama.cpp>/gguf-py sentencepiece protobuf`. Installing gguf-py from a local path
builds it from source in an isolated build environment (poetry-core backend). Since history/034.md, every pip
call runs under `PIP_CONSTRAINT`, and pip also applies it inside that build environment. The exact resolver
message is in the step log; the traceback only showed the exit code.

gguf-py does not need to be installed. `convert_hf_to_gguf.py` puts the checkout's own `gguf-py` first on
`sys.path` unless `NO_LOCAL_GGUF` is set, so the converter always uses the pinned checkout's gguf-py.

A review of the remaining edge-notebook cells found two analysis bugs that would not raise errors but would
produce wrong or empty outputs, and one possible figure crash.

**Modifications:**
- **`notebooks/edge-eval-kaggle/50-install-build.py`:**
  - gguf-py is no longer pip-installed. Only its runtime dependencies and the converter's imports are installed
    (`sentencepiece protobuf pyyaml tqdm requests safetensors "transformers>=5.5.0"`), all as prebuilt wheels and
    still under `PIP_CONSTRAINT`. `NO_LOCAL_GGUF` is unset explicitly.
  - New `llama-convert-check` step: imports the local gguf-py plus all converter dependencies, then runs
    `convert_hf_to_gguf.py --help`. A converter problem now fails in seconds instead of after a 10-30 min merge.
- **`notebooks/edge-eval-kaggle/30-platform-helpers.py`:** `run_step` failures include the last 25 log lines in
  the exception, so the cause shows in the cell output and the ntfy alert.
- **`notebooks/edge-eval-kaggle/120-supplementary.py`:** coverage-vs-accuracy grouping used
  `covered.get(i) is flag`. With a bool-dtype column, `Series.get` returns `numpy.bool_`, which is never
  identical to Python `True`/`False`. Every group was empty and `supp_filter_coverage_vs_ea` held only NaNs.
  The lookup now uses plain Python bools.
- **`notebooks/edge-eval-kaggle/140-figures.py`:** a failed llama-bench quantisation adds a row without `test`.
  `str.startswith` then returned NaN and the boolean mask failed (Figures 3 and 4). Figures now use only
  successful benchmark rows (`na=False`). Figures 2, 5 and 8 also check that their columns exist.
