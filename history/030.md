# Log 030: Defensible Final Evaluation (Prompt Budget, Loud Failures, Neo4j Health, Thesis Statistics)

**Context:**
A review of the final-evaluation pipeline found issues that make the current bundle hard to defend:
about 10% of enhanced-schema evaluation prompts exceed the 2048-token training length (training
trims them, inference did not); a failed final-adapter upload or a Hub error while pulling one was
indistinguishable from "not trained yet"; Neo4j outages were cached as query failures (typo
`servicunavailable` in the unreachable-token list); one demo database (eoflix) fails every gold
query; jobs in the bundle come from different commits and platforms (Gemma fine-tuned on Colab);
and loss curves miss early steps from killed sessions. Training hyperparameters and config
fingerprints are unchanged: new settings live only in non-fingerprinted config sections
(generation, hub, neo4j), and the shared trimming helper reproduces training token ids exactly.

**Modifications:**
- **`src/data/dataset.py`:** `fit_prompt_to_budget()` / `FittedPrompt` extract the schema-trimming
  loop from `tokenize_examples` (render, measure, trim property lines, max 5 attempts; relationship
  patterns protected). `tokenize_examples` uses it with reserve = target length; the left-truncation
  fallback is unchanged, so training features are identical.
- **`src/inference/predict.py`:** prompts are fitted with reserve = `generation.prompt_target_reserve`
  (default `max_new_tokens`), so prompt + generation stays within trained positions. Rows record
  `schema_trimmed`, `prompt_over_budget`, `schema_chars` (after trimming) and `schema_chars_untrimmed`;
  metadata records `n_schema_trimmed`, `n_prompt_over_budget`, `prompt_reserve_tokens`. Trade-off:
  with reserve 256, prompts between about 1792 and 2048 tokens are trimmed at inference although
  training kept them when the target was short; set `prompt_target_reserve` lower to narrow this.
- **`src/config.py`:** `GenerationConfig.prompt_target_reserve`, `HubConfig.metrics_upload_interval_s`
  (3600), `Neo4jConfig.dead_db_policy` ("flag" | "exclude"). None of these sections is fingerprinted.
- **`src/training/train.py`:** exit code 5 when training finishes but the final adapter is not on the
  Hub (push_final failed, or Hub sync was requested but unavailable). Previously only logged.
- **`src/training/checkpointing.py`:**
  - `pull_final()` retries listing and download (3 attempts, backoff) and raises `HubTransferError`
    on Hub errors or incomplete remote folders; returns None only when the listing shows no final adapter.
  - `MetricsMirrorCallback` uploads `metrics.jsonl` to `runs/<run>/telemetry/<T2C_SESSION>/` at most
    once per `metrics_upload_interval_s` (one commit each, skipped while a checkpoint upload holds the lock).
- **`src/training/model_loader.py`:** `target_modules` metadata now counts modules that actually
  received LoRA layers (`_adapted_module_summary`). Unsloth runs previously reported the 12 requested
  leaf names instead of the 186 adapted modules. Existing `run_metadata.json` files keep the old value;
  the final-eval notebook now counts modules from `adapter_model.safetensors`.
- **`app.py`:** `checkpoint pull --step final` exits 0 found / 1 not found / 6 Hub error;
  new `checkpoint push-final`; `evaluate --dead-db-policy`; exit code 5 documented.
- **`src/evaluation/neo4j_client.py`:** fixed the `serviceunavailable` token. Connectivity errors are
  retried with longer backoff, never cached (legacy cached outage failures are ignored), and mark a
  database unreachable only after 3 consecutive failing queries. Rows hit by an outage get status
  `connection_failed` (not scored) instead of counting as model errors. EXPLAIN returns `None` on
  connectivity errors.
- **`src/evaluation/metrics.py`:** execution metrics skip `connection_failed` / `excluded_dead_db`;
  added `execution_accuracy_gold_ok`, `executable_rate_gold_ok`, `n_gold_failed`,
  `n_connection_failed`, `n_schema_trimmed`, `schema_trimmed_rate`, `n_prompt_over_budget`.
- **`src/evaluation/evaluate.py`:** gold-query health per database (failure counts and the most
  common `gold_error` texts, logged and written to the report); databases where 100% of gold queries
  fail are flagged (`dead_database`) or excluded (`--dead-db-policy exclude`); breakdown by
  database access; Gold-Query Health section in the Markdown report.
- **`notebooks/training-kaggle.ipynb`:** exit-5 hint and one automatic `push-final` retry; a
  pull-final Hub error (exit 6) stops the lane instead of retraining; `T2C_SESSION` is passed to
  training for the telemetry folder.
- **`notebooks/final-eval-kaggle.ipynb`:**
  - Expected jobs come from `EXPERIMENTS` regardless of `adapter_ok`; missing or unfinished jobs go
    into `jobs_not_run` and fail an "expected job completed" integrity check.
  - `GIT_REF` pinning check; `EVAL_TAG_SUFFIX` (`r030`) opens a fresh Hub namespace; Hub jobs are
    reused only when commit and platform match (`REUSE_SAME_COMMIT_ONLY`, `REUSE_SAME_PLATFORM_ONLY`);
    per-job `git_commit`, `git_ref` and `platform`; integrity checks and a printed warning for mixed
    commits or platforms.
  - New `cross_schema` job: enhanced-trained adapter with exact-match prompts. Comparison families
    `schema_inference_effect` and `schema_training_effect`.
  - Aggregation: `has_database` stratification (`metrics_by_database_access`,
    `metrics_by_complexity_and_database_access`); headline `Executable` = `executable_rate_gold_ok`;
    bootstrap p-values floored and shown as `< 1/BOOTSTRAP_SAMPLES`; paired bootstrap CI on every
    paired difference plus TOST equivalence (margin `EQUIV_MARGIN`) for schema families; schema
    filtering also analysed on pruned rows only (untrimmed schema ratio < 0.95); zero-shot jobs on
    models without a chat template are labelled "base checkpoint, plain-text prompt"; per-job
    `n_schema_trimmed`; `gold_query_health` table; `connection_failed` / `excluded_dead_db` categories.
  - Telemetry: curves are rebuilt from the newest `runs/<run>/checkpoint-*/trainer_state.json`
    `log_history` on the Hub; `metrics.jsonl` (results/ and the new telemetry/) only fills later steps
    and VRAM; `train_loss_coverage` reports completeness.
  - Latency caveat: s/item is not comparable across platforms or batch sizes.
  - Re-run plan cell.
