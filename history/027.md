# Log 027: Qwen Adapter Never Applied at Inference (Wrapper-Class Key Mismatch)

**Context:**
qwen3.5-2b-exact-match finished training (2448 steps, train loss 0.122, eval loss 0.105) but
scored GLEU 0.1947, EM 0.01 and execution accuracy 0.0612, versus 0.8476 / 0.48 / 0.6531 for
gemma-4-e2b-enhanced. A read-only Colab diagnostic notebook compared the training and inference
loaders.

- **Training (Unsloth):** loads `Qwen3_5ForConditionalGeneration`. The adapter was saved as
  `base_model.model.model.language_model.layers.N...` (372 tensors, all `lora_B` non-zero).
- **Inference (`app.py predict`) and `app.py export merge`:** `AutoModelForCausalLM` resolves to
  the text-only `Qwen3_5ForCausalLM`, with paths `base_model.model.model.layers.N...`.
- **Effect:** Unsloth's `target_modules` regex has a branch that matches the text-only paths, so
  PEFT injected all 372 LoRA modules, but 0 saved tensors matched. PEFT only warned
  ("Found missing adapter keys"), and every `lora_B` stayed at zero.
- **Smoke test:** greedy outputs were identical with and without the adapter on 5/5 rows.
- **Not affected:** prompts (byte-identical between training and inference tokenizers), EOS
  handling (`<|im_end|>` in both), and Gemma (same loader class for training and inference).

**Modifications:**
- **`src/training/model_loader.py`:** `attach_adapter()` wraps `PeftModel.from_pretrained`,
  then reloads the saved tensors with `set_peft_model_state_dict`. Names that differ only by
  the `language_model.` segment are remapped, and only when unambiguous. Unmatched or missing
  tensors, unexpected keys, or all-zero `lora_B` raise instead of warning. Used by
  `load_model_and_tokenizer(adapter_path=...)`. The loaded model class is now logged.
- **`src/export/merge.py`:** uses `attach_adapter()`, so merged weights and GGUFs contain the
  adapter. `merge_metadata.json` records the model class.
