# Log 023: ntfy.sh Push Notifications for the Colab Pipeline

**Context:**
Training sessions run unattended for up to `TIME_LIMIT_MINUTES` (210 min). A crash, a time-limit
pause, or a runtime shutdown was only visible by reopening the notebook. The notebook now pushes
alerts to `ntfy.sh/cxmrykk`.

**Modifications:**
- **`google-colab.ipynb`:**
  - Form fields `NTFY_TOPIC` (default `cxmrykk`, blank disables) and `NTFY_SERVER`
    (default `https://ntfy.sh`).
  - `notify()` uses the standard library (`urllib.request`), so it adds no dependencies. It is
    best-effort and never raises. Titles are forced to ASCII (HTTP headers are latin-1). Bodies
    are capped at 3000 characters so ntfy does not turn them into attachments. Notifications link
    to the Hub logs folder (the results folder on completion).
  - `run_step()` tracks `STATUS["current_step"]` and `STATUS["outcome"]`.
    - Train exit 4 sends a high-priority "paused at time limit" alert with the resume hint.
    - Any other required-step failure sends an urgent alert with the exit code, hint and the last
      15 log lines.
    - A user interrupt sends a high-priority alert.
    - Raised errors are tagged `ntfy_sent` to avoid duplicate alerts.
  - An IPython custom exception handler (`set_custom_exc`) alerts on any other uncaught cell
    error and still shows the normal traceback.
  - SIGTERM and `atexit` hooks (installed once per kernel) send one alert if the kernel ends
    before an outcome is recorded. The alert names the step that was running.
  - Alerts are also sent when the pipeline starts, when training starts (with the expected
    time-limit pause in UTC), and when the pipeline finishes (GLEU / EM / execution accuracy
    from the evaluation report, plus any failed best-effort steps).
  - Intro markdown documents the behaviour.

**Limitations:**
- A hard VM reclaim by Colab (GPU usage limit, idle disconnect, 12 h cap) kills the machine
  without a signal, so no alert can be sent. The "training started" alert gives the time by
  which a pause alert is due; silence past that time indicates a reclaimed runtime.
- ntfy.sh topics are public. Only status text and log tails are sent, never `HF_TOKEN`.
