# History Entry 006: Resolved Colab Download OOM and Tokenization Hang

## Context
When running `download_data.sh` on Google Colab, the environment ran out of disk space/RAM, triggering a Linux `Killed` signal. Colab free tiers only have ~78 GB of storage, and downloading multiple multi-GB models concurrently exhausted it.

Additionally, `app.py train` appeared to hang during data loading. This was not a crash, but rather the tokenization of ~40,000 schemas taking several minutes on Colab's 2-core CPU without user feedback.

## Modifications
1. **`download_data.sh`**: Commented out the unused models (`Gemma-4-E2B`, `Gemma-4-E4B`, `Qwen3.5-4B`). The script now only fetches `text2cypher-2024v1` and `Qwen3.5-2B`, preventing disk exhaustion.
2. **`src/data/dataset.py`**: Added `tqdm` to the main tokenization loop within `tokenize_examples()`. The user can now see a progress bar during the multi-minute data preparation phase, confirming the process is not frozen.
