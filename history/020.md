# Log 020: Set-and-Go Colab Notebook, Unsloth Import Order, Gemma BOS Fix

**Context:**
The Colab notebook should run the whole pipeline for one selected model with `Run all`, and keep
logs when the runtime dies. The diagnostics cell printed Unsloth's "import before transformers/peft"
warning. Reviewing the same output showed the Gemma prompt rendered as plain text without a BOS
token.

**Modifications:**
- **`google-colab.ipynb`:** rewritten as a form-driven pipeline. The first cell selects the model
  (`gemma-4-e2b | qwen3.5-2b | granite-4.2-3b`), schema variant, Hub repo, time limit, prediction
  limit and export options. The download target and Unsloth install follow the selection.
  - `run_step()` streams each command to the cell and to `LOG_DIR/NN-<step>.log`, with tqdm
    redraws collapsed. It mirrors the log to the Hub (`logs/<model>-<variant>/<session>/`) every
    `LOG_UPLOAD_INTERVAL_S` seconds and at step end, and writes `pipeline_status.json`.
  - Optional live logging to Google Drive.
  - Failing steps raise an error so `Run all` stops; the train step maps exit codes 2/3/4 to
    instructions.
  - Training is skipped when a final adapter already exists on the Hub.
  - Predictions, scored rows, reports, `metrics.jsonl` and `run_metadata.json` are uploaded to
    `results/<model>-<variant>/<session>/`.
  - Export (merge, CPU llama.cpp build, Q4_K_M GGUF, optional GGUF upload) is best-effort.
- **`src/env.py`:** package versions are read via `importlib.metadata` instead of importing each
  package. Importing `transformers`/`peft` before `unsloth` caused the warning and patched both
  libraries inside `doctor`.
- **`app.py`:** `train` imports Unsloth before `src.training.train` when `use_unsloth` is
  `auto`/`yes`. Previously `run_training()` imported transformers first, so Qwen runs got only
  partial Unsloth optimisations.
- **`src/logging_utils.py`:** silenced `numexpr` INFO logs ("NumExpr defaulting to N threads").
- **`src/data/prompts.py`:** the plain-text fallback (used by `google/gemma-4-E2B`, a base
  checkpoint with no chat template) now prepends BOS when the tokenizer expects one. All
  tokenization uses `add_special_tokens=False`, so Gemma previously never saw `<bos>`. Added
  `strip_leading_bos()`.
- **`src/inference/llama_cpp_backend.py`:** strips a leading BOS from prompts because
  `llama-server` adds its own (avoids double BOS).
- **`src/training/train.py`:** a wall-clock stop before `max_steps` no longer writes or pushes a
  `final` adapter. It exits with code 4 after the checkpoint upload completes. Previously a
  partially trained adapter was saved as final.
