# Log 033: Incompatible torchao Breaks Adapter Loading on the Kaggle CPU Image

**Context:**
The first edge-eval session (20261015-115853-kaggle-cpu) failed every merge while attaching the LoRA adapter.
The Kaggle CPU image preinstalls torchao 0.10.0. When PEFT injects LoRA layers, it asks each layer backend
whether it can handle a module, including `dispatch_torchao`. `is_torchao_available()` then raises ImportError
for torchao <= 0.16.0 instead of returning False. No torchao layer is involved. The base models themselves
loaded correctly (Gemma4ForConditionalGeneration, Qwen3_5ForCausalLM, GraniteForCausalLM).

**Modifications:**
- **`scripts/colab_bootstrap.sh`:** uninstalls torchao when its version is <= 0.16.0, since the project never
  uses it. This protects every notebook, because `attach_adapter` is also used by predict in final-eval and
  training. torchao was added to the installed-versions printout, and the GPU check now accepts CPU-only
  sessions with a warning.
- **`notebooks/edge-eval-kaggle/50-install-build.py`:** added a `peft-check` step after the bootstrap, so a
  remaining incompatibility fails in seconds instead of after loading every base model.

**Logs & Metrics:**
