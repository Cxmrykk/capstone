# Log 036: llama-server Rejects --no-mmap; Server Options Probed from the Build

**Context:**
The fourth edge-eval session completed exports and llama-bench for all three models. All 10 CPU accuracy jobs then
failed in the first second: the pinned llama.cpp build's `llama-server` exits with
`error: invalid argument: --no-mmap`. `LlamaServer` passed a fixed option list (`-tb`, `--parallel`, `--no-mmap`,
`--no-warmup`) without checking it against the build.

The same failure hit every footprint measurement (`measure_footprint` uses `LlamaServer`). Those errors were stored in
`bench/<model>/bench.json`, and the record was uploaded. Because `80-plan.py` reused any bench record whose commit, CPU
and rows matched, later sessions would never have measured the footprint again.

**Modifications:**
- **`notebooks/edge-eval-kaggle/100-bench.py`:**
  - Runs `llama-server --help` once and saves it to `llama-server-help.txt` in the session log folder.
  - Required options (`-m`, `-c`, `-t`, `--host`, `--port`) must be listed. Optional ones (`-tb`, `--parallel`,
    `--no-warmup`) are passed only if listed.
  - Memory mapping uses `--no-mmap` if listed. Otherwise it uses the `LLAMA_ARG_*MMAP*` environment variable named in
    the help text. Otherwise it stays at llama.cpp's default (mmap on), which is recorded.
  - If the server still exits with `invalid argument: X`, `X` is dropped and the start is retried (up to 3 times;
    required options are never dropped). If the server fails while the mmap environment variable is set, it is retried
    once without it.
  - A smoke test (smallest local GGUF, 1-token request) runs before any benchmark or job, so a server that cannot start
    stops the session immediately.
  - The footprint also records `rss_after_first_request_mb`, `mmap_mode` and the server command.
  - Bench records store the server command template. When the llama-bench rows came from an earlier session,
    `bench_rows_session` records which one.
- **`notebooks/edge-eval-kaggle/80-plan.py`:**
  - A Hub bench record is reused only if its llama-bench rows have no errors and every `LATENCY_QUANTS` footprint
    succeeded.
  - If only the footprint is incomplete, the llama-bench rows are kept (`REUSED_BENCH_ROWS`) and only the footprint is
    measured again.
  - `_provenance()` adds `server_mmap_mode`.
- **`notebooks/edge-eval-kaggle/150-bundle.py`:**
  - The manifest records the server command template, mmap mode and environment, mmap help lines, rejected options and
    the smoke-test result.
  - The README's footprint definition and caveats follow the mmap mode actually used. With mmap on, `load_s` excludes
    most weight reads; these show up in `first_request_ms` and `rss_after_first_request_mb`.
