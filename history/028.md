# Log 028: Final Evaluation Notebook (Colab T4, Thesis Results Bundle)

**Context:**
All models are trained on Kaggle (history/024.md, history/025.md). The Qwen adapters were
evaluated before the wrapper-class fix (history/027.md), so earlier Qwen predictions, reports
and GGUFs reflect the base model. A single, reproducible final evaluation on Colab is needed
to produce the thesis numbers as structured data. `final-evaluation.ipynb` pulls each final
adapter from the Hub and scores every experiment on identical test rows, plus a zero-shot
control for each, then writes tables, per-row data, JSON and figures.

**Modifications:**
- **Added `final-evaluation.ipynb`** (no changes to `src/`, configs or scripts):
  - **Protocol:** one seeded sample of the test split (`EVAL_LIMIT`, default 500, seed taken from
    the configs and checked to be identical across them) is shared by every job, so jobs can be
    compared pairwise. Decoding is greedy; batch size and `max_new_tokens` come from each config.
    `EVAL_LIMIT = None` runs the full split via an explicit limit (otherwise `predict` caps at
    `data.max_eval_samples`).
  - **Jobs:** for each of the five experiments, one `fine_tuned` job (adapter from
    `runs/<run_name>/final`) and one `zero_shot` job (same base model, prompts, schema mode and
    rows, no adapter). Optional `RUN_GGUF_CPU_BENCH` adds a Q4_K_M GGUF job on the Colab CPU over
    a subset of the same rows. Each job runs `app.py predict` then `app.py evaluate --execute
    --validate-syntax`.
  - **Provenance guards:**
    - The notebook refuses to run on a checkout without `attach_adapter` / `Adapter verified`.
    - A fine-tuned HF job fails if its predict log has no `Adapter verified` line. A zero-shot
      job fails if an adapter was loaded.
    - Qwen GGUFs without `model_class` in the merge metadata (pre-fix merges) are skipped.
    - Integrity table checks: identical instance sets across GPU jobs, adapter verification,
      fine-tuned outputs not >=90% identical to zero-shot, gold-query failure rate below 5%,
      and training fingerprint vs current config.
  - **Resume:** each finished job is uploaded as one commit to
    `final-eval/<eval_tag>/jobs/<job_id>/`. With `SKIP_COMPLETED_JOBS`, a fresh runtime
    downloads finished jobs instead of recomputing them. `MAX_SESSION_MINUTES` stops starting
    new jobs; Run all again continues.
  - **Training telemetry:** merges every session's `results/<model>-<variant>/<session>/metrics.jsonl`
    from the Hub (de-duplicating steps repeated after a resume) into a training summary and
    loss curves, joined with each adapter's `run_metadata.json`.
  - **Statistics:** Wilson intervals for proportions, percentile bootstrap for corpus GLEU
    (`BOOTSTRAP_SAMPLES`, `STATS_SEED`), exact McNemar for binary metrics, paired bootstrap for
    mean sentence GLEU, Holm correction within each family x metric. Comparison families:
    fine-tuning effect, schema filtering, model comparison, and 4-bit GPU vs GGUF CPU.
  - **Execution accuracy:** `execution_accuracy` counts only rows with an executable gold query;
    `execution_accuracy_toolkit` (all executed rows, as in `app.py evaluate`) is kept alongside.
    Error categories: correct, wrong_result, invalid_query, runtime_error, execution_error,
    empty_output, gold_failed, not_executed.
  - **Outputs** (`artifacts/thesis/<eval_tag>/`): `tables/*.csv` (headline + `.tex`, overall,
    by complexity / data source / database, error categories, paired tests, schema filtering,
    training summary and curves, integrity checks, jobs, published baselines),
    `predictions_long.parquet` and `.csv.gz`, `results.json`, `manifest.json` (commit, GPU,
    package versions, settings), `README.md` with metric definitions and caveats, figures
    (PNG 300 dpi + PDF), and a zip. The bundle is uploaded to
    `final-eval/<eval_tag>/thesis/<session>/` and can be copied to Drive or downloaded.
  - **Notifications:** ntfy alerts (start, job failure, jobs finished, notebook error, runtime
    ended, finished), same conventions as history/023.md.
  - `PUBLISHED_BASELINES` is left empty by design: literature numbers (e.g. Ozsoy et al., 2025)
    are entered by hand and kept in a separate table, never mixed with measured results.
