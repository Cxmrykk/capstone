# Log 018: Scope Reduction to 2B Models & Return to Google Colab (T4)

**Context:**
UTS CETUS access (history/017.md) has not materialised in time for the training schedule, and
GCP / Lightning AI remain locked (015, 016). The project returns to Google Colab's free T4 (16 GB,
Turing sm_75, no bf16) and is scoped to 2B-parameter models only: Gemma 4 E2B and Qwen3.5-2B.
The 4B variants are dropped from the codebase. The original T4 failure (history/014.md) was caused by
Unsloth upcasting Gemma 4 to fp32 plus full-sequence logits over a 262k vocabulary; this entry
addresses both directly instead of moving hardware.

**Modifications:**
- **Removed:** `configs/gemma-4-e4b.yaml`, `configs/qwen3.5-4b.yaml`, `SETUP.md` (GCP guide), the
  `data/gemma-4-E4B` and `data/Qwen3.5-4B` submodules; 4B entries removed from `MODEL_REGISTRY`,
  aliases, `env.py`, `.gitmodules` and `data/0-sample/data.py`.
- **Added `scripts/colab_bootstrap.sh`:** the restored notebook depends on it. Installs requirements,
  optional Unsloth, and re-asserts the transformers floor Unsloth may downgrade.
- **Added `configs/gemma-4-e2b-pruned.yaml`:** gives the schema-filtering sub-question a Gemma arm
  to match `qwen3.5-2b-pruned.yaml`.
- **`src/paths.py`:** artifacts now always live in `<repo>/artifacts`. On Colab they previously went
  to `/content/artifacts`, which broke the notebook's relative adapter/merge paths. Colab detection
  now also reads `COLAB_RELEASE_TAG` so `!python` subprocesses are recognised.
- **`src/training/train.py`:** `TargetOnlyLossTrainer` requests logits only for the trailing target
  span (`logits_to_keep`), since prompt tokens are masked anyway. `prediction_loss_only=True` stops
  evaluation from gathering full-vocabulary logits for all validation rows. Text-only
  `token_type_ids` are supplied to Gemma. Clear guidance on CUDA OOM.
- **`src/training/model_loader.py`:** lean k-bit preparation that keeps frozen weights in fp16
  (PEFT's helper upcasts Gemma's per-layer embedding tables to fp32); LoRA weights are forced to
  fp32 for the fp16 GradScaler. Behaviour switchable with `model.upcast_frozen_params`.
- **`src/training/checkpointing.py`:** `NonFiniteLossGuard` stops a diverging fp16 run before a
  useless adapter is saved; `pull_final()` restores a finished adapter into a fresh Colab session
  (`app.py checkpoint pull --step final`).
- **`src/inference/predict.py`:** prompt token counting now uses `text=` + `_flatten_ids`
  (same multimodal processor bug as history/005.md).
- **Gemma configs:** `use_unsloth: "no"`, batch 1 x accumulation 16, SDPA attention
  (Gemma 4 text layers have no attention softcapping).
- **`requirements.txt`:** transformers floor raised to match the Gemma 4 config's
  `transformers_version`.
- **`download_data.sh`:** sequential, selectable downloads (`all | gemma | qwen | dataset`).

**Logs & Metrics:**
- Fingerprints changed (new config fields), so remote checkpoints from earlier attempts will be
  refused on resume; runs restart from scratch with `--resume none` or new run names.
- Pending: first T4 run telemetry (peak VRAM, s/step, loss curve) for gemma-4-e2b-enhanced.
