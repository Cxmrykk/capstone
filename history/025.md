# Log 025: Parallel Lanes on Kaggle T4 x2 & Hub Log Mirroring Removed

**Context:**
A single-lane Kaggle notebook (history/024.md) leaves the second T4 idle while the weekly
GPU quota is charged per session-hour, so about half the compute per quota hour was wasted.
Data-parallel training was rejected: it needs torchrun, rank-0-only Hub sync, synchronised
stop decisions, and a halved `gradient_accumulation_steps`, which changes the fingerprint.
Instead, each notebook runs up to two independent experiments, one per GPU, each keeping the
validated single-GPU maths. Separately, several instances on several accounts hit the Hub
commit rate limit (120 commits/hour), mostly from log mirroring (one commit per step log every
`LOG_UPLOAD_INTERVAL_S`, plus status uploads).

**Modifications:**
- **`kaggle.ipynb` (rewritten):** template for three notebooks that differ only in cell 1:
  `kaggle-gemma.ipynb` (gemma-4-e2b enhanced + pruned), `kaggle-qwen.ipynb` (qwen3.5-2b
  enhanced + pruned), `kaggle-granite.ipynb` (granite-4.2-3b enhanced, single lane).
  - `LANES` = list of (model, variant, GPU). Validation: at most two lanes, distinct
    model/variant, distinct GPUs, distinct run names; P100 refused; a missing GPU index fails
    fast.
  - Shared steps (clone, bootstrap, per-model downloads in sequence, doctor, previews) run
    once. Lane pipelines (pull-final, train, predict, evaluate, export) run in worker threads.
    Each step is a subprocess with `CUDA_VISIBLE_DEVICES=<lane GPU>`, so every trainer sees
    one device (no DataParallel, `device_map={"": 0}` unchanged).
  - Each lane runs from its own cwd (`<scratch>/lanes/<lane>`) with absolute paths to `app.py`,
    configs and artifacts, so cwd-relative caches (e.g. Unsloth compiled cache) cannot
    collide. Lane starts are staggered by `LANE_STAGGER_S` (default 90 s).
  - Merge and GGUF export are serialised behind a lock (disk; shared llama.cpp checkout).
    llama.cpp is built once. Merged fp16 weights are deleted after conversion unless
    `KEEP_MERGED`.
  - Lane output goes to log files only; a heartbeat (`HEARTBEAT_S`) prints each lane's step,
    duration, latest log line (including tqdm progress), GPU memory/utilisation, available RAM
    and free disk.
  - A paused, out-of-time or failed lane does not stop the other lane. Interrupts and SIGTERM
    set a stop event and send SIGINT to every running step, so trainers write emergency
    checkpoints.
  - `RESERVE_MINUTES` raised 75 -> 90 because the second lane may wait for the export slot.
  - **Hub logs removed:** no log or status mirroring. Logs live in
    `/kaggle/working/text2cypher-logs/<instance>/<session>/<lane>/` (saved with the version).
    Each lane uploads its `results/` folder plus `lane_status.json` in one commit at lane end
    (`UPLOAD_RESULTS_TO_HUB`). GGUFs are one commit each. ntfy links point to results, not logs.
- **Unchanged:** `src/`, configs, `scripts/`, `google-colab.ipynb` (still mirrors logs to the
  Hub; fine while Colab is not run alongside the Kaggle instances).

**Logs & Metrics:**
- Remaining Hub commits come from checkpoint sync: about 3 per save (checkpoint folder,
  LATEST marker, prune). At about 25 s/step and `save_steps: 50` that is about 9/hour per
  lane, about 45/hour for five lanes, plus a few results/final/GGUF commits per lane. If the
  limit is still hit, raise `train.save_steps` (excluded from the fingerprint, so resume is
  unaffected) or merge the three checkpoint commits into one `create_commit`.
